# OL-Arts

OL-Arts — сайт-портфолио и блог для малого бизнеса и самопрезентации автора. Посетители могут знакомиться с галереей работ, публикациями и услугами; предусмотрены вход через Google и административные страницы для управления контентом.

## Технологии и зависимости

- **Next.js 16**, **React 19**, **TypeScript 7** — приложение и пользовательский интерфейс.
- **PostgreSQL** — реляционная база данных; для локальной разработки доступен Docker Compose.
- **Prisma 7** (`prisma`, `@prisma/client`) — схема, миграции и типизированный доступ к данным.
- **Neon** (`@neondatabase/serverless`, `@prisma/adapter-neon`) — подключение к PostgreSQL в Neon через serverless-адаптер.
- **Auth.js / NextAuth 5 beta** и `@auth/prisma-adapter` — аутентификация Google и хранение учетных данных в Prisma.
- **Tailwind CSS 4** и `@tailwindcss/postcss` — стили.
- **dotenv** — загрузка переменных окружения для Prisma.
- **lucide-react** — иконки.
- **tsx** — запуск TypeScript seed-скрипта.

Все прямые зависимости из `package.json` установлены в проверенной локальной копии. Отдельных зависимостей для тестов, линтинга, валидации входных данных или загрузки изображений сейчас нет. `@neon/config` используется в `neon.ts`; `@neon/env` и импорт `Pool` в `src/lib/prisma.ts` выглядят неиспользуемыми в прикладном коде и могут быть проверены на удаление отдельно. Neon Auth в `neon.ts` отключен; переменные `NEON_AUTH_*`, `NEON_BRANCH` и `DATABASE_URL_UNPOOLED` сейчас приложением не читаются.

## Требования

- Node.js, совместимый с Next.js 16.
- npm.
- Docker Desktop (для локального PostgreSQL) **или** доступная база PostgreSQL/Neon.
- OAuth-клиент Google для входа.

## Быстрый старт

Команды выполняются из корня репозитория в PowerShell.

```powershell
npm install
Copy-Item example.env .env
```

Заполните `.env` перед запуском. Обязательные переменные:

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | Строка подключения PostgreSQL; используется приложением и Prisma CLI |
| `GOOGLE_CLIENT_ID` | OAuth Client ID из Google Cloud Console |
| `GOOGLE_CLIENT_SECRET` | OAuth Client Secret из Google Cloud Console |
| `NEXTAUTH_SECRET` | Секрет для подписи сессий Auth.js |
| `NEXTAUTH_URL` | Базовый URL приложения, например `http://localhost:3000` |

### Локальная база PostgreSQL в Docker

В `compose.yaml` настроен порт хоста `5433`, а PostgreSQL внутри контейнера слушает `5432`:

```powershell
docker compose up -d
```

Укажите пароль, совпадающий с `POSTGRES_PASSWORD` в `compose.yaml`, в строке подключения:

```text
DATABASE_URL="postgresql://postgres:<пароль>@localhost:5433/Testdb?schema=public"
```

### Команды проекта

| Команда | Описание |
| --- | --- |
| `npm run dev` | Запустить сервер разработки |
| `npm run build` | Собрать production-версию |
| `npm run start` | Запустить собранное приложение; сначала выполните `npm run build` |
| `npx prisma validate` | Проверить схему Prisma |
| `npx prisma generate` | Сгенерировать Prisma Client после изменения схемы |
| `npx prisma migrate status` | Проверить примененные и ожидающие миграции для `DATABASE_URL` |
| `npx prisma migrate dev --name <имя>` | Создать и применить миграцию в локальной/разработческой базе |
| `npx prisma migrate deploy` | Применить готовые миграции в целевой базе, например при развертывании |
| `npx prisma db seed` | Запустить seed-скрипт, настроенный в `prisma.config.ts` |
| `docker compose up -d` | Запустить локальный PostgreSQL в фоне |
| `docker compose down` | Остановить контейнеры, сохранив данные в Docker volume |

Перед запуском приложения примените миграции и сгенерируйте клиент:

```powershell
npx prisma migrate dev
npx prisma generate
npm run dev
```

Для production не используйте `migrate dev`: применяйте уже созданные и проверенные файлы миграций командой `npx prisma migrate deploy`. Не редактируйте миграции, которые уже применены к общей или production-базе.

## Состояние и план улучшений

1. **Защитить API управления контентом.** Проверять сессию и роль администратора непосредственно в обработчиках `POST`, `PUT` и `DELETE` для данных галереи и публикаций. Сейчас middleware сопоставлен с `/Admin-page/:path*`, а API-обработчики данных не выполняют такую проверку.
2. **Добавить валидацию и тесты.** Валидировать входные данные на сервере (например, Zod), настроить проверки TypeScript/lint и тестирование API и авторизации. Скрипт `npm test` пока заглушка и не запускает тесты.
3. **Завершить управление контентом.** Определить модель услуг и проверить, какие изменения админки действительно сохраняются в БД; сейчас в Prisma-схеме есть модели `Gallery`, `Post` и авторизации, но отдельной модели услуг нет.
4. **Организовать хранение изображений.** Сейчас схема хранит строковое поле `image`; выбрать хранилище файлов и правила загрузки/удаления, если изображения будут загружаться через админку.
5. **Улучшить производительность и доступность.** Проверить `images.unoptimized: true`, включить оптимизацию изображений при подходящем хостинге, добавить пагинацию/ограничение выборок и проверить адаптивность и доступность интерфейса.
6. **Обновить конфигурацию Next.js.** Перенести устаревшую конвенцию `middleware` на `proxy` для Next.js 16 и явно задать корень Turbopack, чтобы устранить предупреждения сборки.
7. **Уточнить конфигурацию окружений и зависимости.** Разделить настройки локальной базы, Neon и production; удалить неиспользуемые переменные/пакеты после проверки и планировать выход с NextAuth 5 beta на стабильную версию, когда она будет совместима с проектом.

Новые пакеты (например, Zod, ESLint или тестовый фреймворк) намеренно не добавлялись: сначала стоит выбрать требуемые проверки и сценарии тестирования.
